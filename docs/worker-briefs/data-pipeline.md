# Worker brief — data-pipeline

## Mission

Own the ingest path from a user's TikTok export to a normalized,
inference-ready collection of videos and watch events. Build the importer,
the yt-dlp wrapper, and the preprocessor. Cache aggressively so
re-running the pipeline is cheap.

## Owned files / directories

- `services/pipeline/**` — create this package. Suggested layout:
  - `services/pipeline/neural_media_pipeline/__init__.py`
  - `services/pipeline/neural_media_pipeline/importer.py` — TikTok export
    JSON → `VideoMetadata` + `WatchEvent` rows.
  - `services/pipeline/neural_media_pipeline/downloader.py` — yt-dlp
    wrapper with retry, jitter, dedup.
  - `services/pipeline/neural_media_pipeline/preprocess.py` — resize /
    re-encode / audio sample-rate normalization via ffmpeg.
  - `services/pipeline/neural_media_pipeline/orchestrate.py` — the
    download → preprocess → infer queue (start with a SQLite-backed
    job queue; do not pull Redis until you can justify it).
  - `services/pipeline/tests/**`
- `services/pipeline/pyproject.toml`
- The structure of `data/sample/tiktok_export/user_data.json` — you own
  the format the importer parses, so if TikTok's export format drifts,
  you update the fixture.

## Files this worker must NOT touch

- `shared/**` — contracts.
- `services/inference/**`, `services/api/**` — peers.
- `apps/web/**`.
- `data/sample/mock_inference/**` — that is generated by ml-inference's
  build script from your fixture.

## Deliverables

1. **Importer**: reads a TikTok export and emits
   `VideoMetadata` + `WatchEvent` dicts that round-trip through
   `shared.schemas`. Tolerant of missing fields (the export shape is not
   fully stable across TikTok updates).
2. **Downloader**: pulls videos via yt-dlp with retry on
   rate-limit / network errors, exponential backoff with jitter, and a
   dedup cache keyed by stable video id (CONTRACTS.md §1). Files land
   under `data/videos/{video_id}.mp4`.
3. **Preprocessor**: produces inference-ready video files. Resolution,
   FPS, and audio sample rate are pinned (coordinate with ml-inference
   on the exact TRIBE-expected values before shipping; log them into
   the reproducibility envelope via `extra_params`).
4. **Orchestrator**: a small SQLite-backed job queue that drives
   download → preprocess → infer for a whole export end-to-end. Resumable.
   Idempotent.

## Interfaces this worker must preserve

- `VideoMetadata` and `WatchEvent` shapes from `shared/schemas.py`.
- `data/videos/{video_id}.mp4` is the canonical local path for a
  downloaded video (api-orchestrator may surface this).
- The orchestrator's hand-off into ml-inference is a call to
  `neural_media_inference.run_inference(...)`. Pass `extra_params` with
  preprocessing config so it lands in the reproducibility sidecar.

## How to test the work

```
cd services/pipeline
pip install -e '.[dev]'
pytest -q
```

Smoke tests should cover:

- The committed fixture `data/sample/tiktok_export/user_data.json`
  parses cleanly and produces the expected 8 `WatchEvent` rows.
- Stable video ids: parsing the same URL twice yields the same id.
- The downloader is mockable — tests should not hit TikTok.
- Preprocess produces files at the documented resolution / FPS / sample
  rate.

## Scientific-framing constraints

- Watch history is sensitive. Do not log full URLs or thumbnails in
  any output that leaves the machine.
- Never call the videos directory anything other than "downloaded
  videos." Avoid "training data" or "your media diet" framings here.

## Out of scope for this worker

- Running the model itself — that is ml-inference.
- HTTP / API surface — that is api-orchestrator.
- Any frontend.
- A multi-user job queue, auth, rate limiting beyond yt-dlp's own
  retries.
