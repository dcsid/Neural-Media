# Worker brief — data-pipeline

## Mission

Own the ingest path from a user's TikTok export to a normalized,
inference-ready collection of videos and watch events. Build the importer,
the yt-dlp wrapper, and the preprocessor. Cache aggressively so
re-running the pipeline is cheap.

## Owned files / directories

- `services/pipeline/**` — create this package. Suggested layout:
  - `services/pipeline/neural_media_pipeline/__init__.py`
  - `services/pipeline/neural_media_pipeline/importer.py` — TikTok export
    JSON → `VideoMetadata` + `WatchEvent` rows.
  - `services/pipeline/neural_media_pipeline/downloader.py` — yt-dlp
    wrapper with retry, jitter, dedup.
  - `services/pipeline/neural_media_pipeline/preprocess.py` — resize /
    re-encode / audio sample-rate normalization via ffmpeg.
  - `services/pipeline/neural_media_pipeline/orchestrate.py` — the
    download → preprocess → infer queue (start with a SQLite-backed
    job queue; do not pull Redis until you can justify it).
  - `services/pipeline/tests/**`
- `services/pipeline/pyproject.toml`
- The structure of `data/sample/tiktok_export/user_data.json` — you own
  the format the importer parses, so if TikTok's export format drifts,
  you update the fixture.

## Files this worker must NOT touch

- `shared/**` — contracts.
- `services/inference/**`, `services/api/**` — peers.
- `apps/web/**`.
- `data/sample/mock_inference/**` — that is generated by ml-inference's
  build script from your fixture.

## Deliverables (current state)

The first four landed in rounds 1–3; everything below is shipped and
should not be re-implemented — extend instead.

1. **Importer**: reads a TikTok export and emits
   `VideoMetadata` + `WatchEvent` dicts that round-trip through
   `shared.schemas`. Auto-detects three input formats:
   - `user_data.json` (older TikTok exports — JSON, traversed at
     `Activity > Video Browsing History > VideoList`)
   - `Watch History.txt` (newer TikTok exports — flat
     `Date:`/`Link:` blocks with a `" UTC"` suffix on the timestamp)
   - `.zip` (the full archive; `user_data.json` is read in-memory at
     any depth without extraction)
   Accepts `since` / `until` kwargs (both UTC, half-open window) so
   the inference workload can be capped at parse time before yt-dlp
   ever runs. Tolerant of missing fields.
2. **Downloader**: pulls videos via yt-dlp with retry, exponential
   backoff + jitter, UA rotation, dedup cache. Files land under
   `data/videos/{video_id}.mp4`. The newer
   `tiktokv.com/share/video/<id>/` share-shortlink URL form is
   supported by yt-dlp's TikTok extractor — `scripts/probe_share_url.py`
   verifies this end-to-end. `yt_dlp_available()` helper feeds the
   api worker's `/capabilities` endpoint.
3. **Preprocessor**: ffmpeg → 224×224 @ 8 fps + 16 kHz mono.
   Resolution/FPS/sample rate are imported directly from
   `neural_media_inference.runner.DEFAULT_PREPROCESSING_PARAMS` so
   drift is physically impossible. Logs into the reproducibility
   envelope via `extra_params`. `ffmpeg_available()` helper feeds
   the api worker's `/capabilities`.
4. **Orchestrator**: SQLite-backed job queue driving download →
   preprocess → infer per video. Resumable, idempotent.
   `OrchestratorConfig` knobs:
   - `skip_download`, `skip_preprocess` (mock-mode toggles)
   - `purge_after_inference` (tier-a cleanup: drops raw +
     preprocessed `.mp4`s after `RegionMetrics` persist; keeps peak
     transient disk to ~10 MB)
   - `purge_activations` (tier-b cleanup: additionally drops the
     20484-vertex `.npz` and JSON sidecar; brain-viz handles the
     missing per-vertex data via `PlaceholderMesh` fallback)
   - `compress_activations` (opt-in zlib compression on persistence)
5. **CLI** (`python -m neural_media_pipeline`): mirrors orchestrator
   options. Time-window flags collapse to a single `since` (finest
   unit wins): `--minutes N` > `--hours N` > `--days N` > `--since`
   (ISO). `--purge-after-inference` and `--purge-activations` are
   independent.

## Interfaces this worker must preserve

- `VideoMetadata` and `WatchEvent` shapes from `shared/schemas.py`.
- `data/videos/{video_id}.mp4` is the canonical local path for a
  downloaded video (api-orchestrator may surface this).
- The orchestrator's hand-off into ml-inference is a call to
  `neural_media_inference.run_inference(...)`. Pass `extra_params` with
  preprocessing config so it lands in the reproducibility sidecar.

## How to test the work

```
cd services/pipeline
pip install -e '.[dev]'
pytest -q
```

Smoke tests should cover (current suite: 94 tests passing):

- Both fixtures parse cleanly: `data/sample/tiktok_export/user_data.json`
  and `data/sample/tiktok_export/watch_history.txt` each yield 8
  `WatchEvent` rows.
- `_parse_date` accepts naive timestamps, `"%Y-%m-%dT%H:%M:%S"`, and
  the `" UTC"` suffix from the .txt format.
- Date-window filter: `parse_export(..., since=..., until=...)` keeps
  exactly the in-window events, drops a video iff it has no in-window
  events.
- Stable video ids: parsing the same URL twice yields the same id.
  (`tiktok.com/@handle/video/<id>` and `tiktokv.com/share/video/<id>/`
  hash to different ids — they are different URLs even if they resolve
  to the same video.)
- The downloader is mockable — tests must not hit TikTok.
- Preprocess produces files at the documented resolution / FPS / sample
  rate.
- Cleanup hooks: `--purge-after-inference` removes mp4s but keeps
  activations; `--purge-activations` removes activations but keeps
  region_metrics rows.

## Scientific-framing constraints

- Watch history is sensitive. Do not log full URLs or thumbnails in
  any output that leaves the machine.
- Never call the videos directory anything other than "downloaded
  videos." Avoid "training data" or "your media diet" framings here.

## Out of scope for this worker

- Running the model itself — that is ml-inference.
- HTTP / API surface — that is api-orchestrator.
- Any frontend.
- A multi-user job queue, auth, rate limiting beyond yt-dlp's own
  retries.
